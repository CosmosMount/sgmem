# 实验协议

本协议约束实验设计；Part 1 四域全量基线及 Part 2 开发样本分析已完成，2026-11-10 另补充公开查询元数据诊断，实际设置、偏差与结果见 [Part 1/2 全量报告](part12-full-results.md)。后续代码统一从 GitHub 最新 `main` 开始；下列涉及 SGAR 和消融的步骤仍是方案，优先级见 [实施路线图](roadmap.md)。

## 阶段与对照

1. 核验上游数据、可见性、许可证和评测规则，在合成样例和少量真实样例上贯通数据 → 检索 → 本地 QA → 评测 → 轨迹。测试不得依赖下载大模型。
2. 先运行 BM25 与 Dense 本地基线，对开发集的错误进行分类，确认值得解决的问题。Finance 和 Technology 是优先候选，具体范围与题型以数据核验结果为准。
3. 基于开发集设计 SGAR，并选择候选池 M、特征、归一化和权重；记录开发过程与失败尝试。主对照是 BM25、Dense、BM25+SGAR、Dense+SGAR；资源不够时先完成最有价值的配对。各特征消融与 K 敏感性单独报告。
4. 固定代码、配置、划分、QA 模型与评测后运行 test。报告整体与各题型的题数、准确率和配对变化，以及有代表性的修复和新错误；不支持的改善不应宣称成立。若不同方法因失败而覆盖题目不同，报告失败数量和处理规则，不只比较幸存样本。

所有主对照采用相同问题 ID、可见语料、最终 K、上下文 token 上限、上下文格式、QA 模型和解码参数、judge 与规则。候选池 M、检索与重排序的差异应明确；模型调用失败及 judge 失败不得默默计为正确或丢弃。SGAR 先用基础检索器，再用仅基于公开输入的元数据重排；所有变体记录模型 prompt 和版本。官方基线如使用不同模型或评测条件，不可直接把分数当作精确复现比较。

## 划分和防泄漏

本次已固定按领域、题型分层的 question-level 划分：dev 179 题、test 536 题，清单为 `docs/evidence/part12-full-20261105/split.json`。后续方法沿用这些 ID，不重新抽取。两组共享历史对话；报告应说明同一对话及问题家族关联，不能据此声称跨对话泛化。两者不得重叠，切分脚本应验证覆盖和唯一性。

检索模块接收不含 gold 答案、标注证据或正确 group 的查询；判分所需 gold 只进入 evaluator。适用时过滤提问时点之后、权限范围之外的消息，依据上游任务规则确定可见历史，而非默认全部历史均可见。同一历史语料可服务多题，但这属于共享语料设定，不等同于跨对话泛化。test 冻结后仅做事后诊断；任何基于 test 的改动须声明 test 已被使用，并准备独立评估集，不能继续把它称为未使用的最终测试集。

## 失败分析

保留多标签和唯一主标签：speaker 混淆、group 混淆、观点归属、回复上下文、时间更新、跨参与者推理、其他检索错误、QA 推理错误。先核实所需证据是否存在且已检索，再区分检索不足和证据充分但回答错误；证据 ID 和人工标注只供分析/评测，不进入检索。记录抽样方法、每类分母、标注者、判定依据与分歧处理；小样本结果作为诊断而非总体比例的可靠估计。

## 成本与性能

按阶段记录索引构建、检索、重排序、QA 和 judge 的 wall-clock、CPU 时间、峰值内存、GPU 型号与数量、峰值显存、GPU 占用时长和输入/输出 token 数。BM25 的检索可用 CPU，但其 QA/judge 若用 GPU 也必须计入 GPU-hours。报告一次性 embedding/index 成本和每题增量成本，明确缓存命中、冷/热启动、batch size、并发、计时边界、预热、硬件、软件版本及统计方式；共享阶段分别说明总成本和摊分规则，避免重复计数。GPU-hours 用实际占用的 GPU 数乘对应时长，记录测量方法和不确定性；它不等于利用率积分。

实验前做小批量测量，估算剩余预算；每次在共享看板登记 GPU 数、预期占用与实际花费。最终项目 PDF 已确认 Topic 12 要求小于 50 GPU-hours；本次全量基线为 3.5907 GPU-hours，历史试跑和预检另计，不能把该数字当作整个项目累计。最终用真实测量比较质量和成本，不虚构数据。

## 运行产物与复现

正式实验统一使用 `results/runs/<run_id>/`，按需要保存：临时 smoke test 和调试输出使用临时目录并在对话结束前清理。

```text
config.yaml             # 解析后的完整配置
manifest.json           # 代码 commit、dirty 状态、运行 ID、split、来源与版本等
predictions.jsonl       # 每题生成结果及状态
retrieval_trace.jsonl   # 每题候选、分数和最终证据顺序
evaluation.jsonl        # 每题判分、失败状态、judge 版本
resource_usage.json     # 阶段计时、硬件及消耗
metrics.json            # 聚合指标、分母与失败数
```

manifest 还应记录数据源版本、模型及 tokenizer revision、prompt 版本、随机种子、软件/硬件、起止时间、缓存键及产物位置；需要恢复长时间运行时，可使用逐题检查点；运行完成后清理不再需要的临时检查点。保留报告和复现所需的正式结果，修正正式运行时避免覆盖证据并记录关系；调试或失败尝试不默认长期保存。正式报告使用已提交的代码及冻结配置；如工作树有未提交变化，记录 diff 或禁止将该运行用于最终结果。随机种子不能保证所有硬件和推理后端完全确定，记录可能的非确定性。

报告表格和图引用 run ID 及生成脚本，保存结果存储地址和访问方式，允许另一成员从记录追溯一个数值到逐题结果。小型合成样例可入库；真实数据及结果共享前核查许可和敏感信息。
