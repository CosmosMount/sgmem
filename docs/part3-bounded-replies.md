# Part 3 · 有界回复扩展

`bm25-reply` 用回复关系补回被词面检索漏掉的消息。它与 Part 1 的 BM25 共用内容分数、稳定排序和相同的最终上下文大小。下列实验使用已发布的四域开发集，179 题。数据修订、划分摘要、逐题变更与回复路径都在[检索记录](evidence/bounded-reply-dev.json)中。

## 方法

1. BM25 检索公开的提问者 ID 和问题文本。问题出现建议、提案、讨论、反馈或回复等英语线索时，才启用扩展。完整词表在[检索实现](../src/sgmem/retrieval.py)中。
2. 最终取十条时，固定原前八条，从这八条沿同一群组的父消息或子回复走至多两跳，可找到同一父消息下的另一条回复。每个节点最多看一个父节点和八个子节点。若子回复超过八条，只看按时间排序的最早四条、最晚四条，中间的证据可能因此漏掉。
3. 候选按自身 BM25 分数排序。同分优先原前十中的消息，再优先较短路径和原语料顺序。只有正分且至少达到原第十名分数一半的回复能竞争末尾两个位置。空位由原排序补齐，消息 ID 去重。进模型的仍是十条消息，图中的路径单独留在检索记录里。

每题只做一次内容打分。扩展最多检查 `8 × (9 + 9²) = 720` 次邻接关系，诊断记录最多保留原十条和十条新增候选。标注支持 ID 只参与事后核对。

## 固定开发集的检索结果

改动题数统计 179 题中前十成员与 BM25 不同的题数。其余各列只统计 **15 条有支持消息标注的 BM25 开发集失败记录**。每条命中表示至少一条已标注支持进入相应集合。两项原始基线只有已保存的前十可供比较。

| 方法 | 改动题数 / 179 | 候选池命中 / 15 | 最终前十命中 / 15 | 较 BM25 新增 / 丢失 |
|---|---:|---:|---:|---:|
| 原 BM25 | 0 | 4 | 4 | 0 / 0 |
| 原 E5 Dense | 179 | 5 | 5 | 2 / 1 |
| 一跳、两个位置 | 15 | 4 | 4 | 0 / 0 |
| 两跳、一个位置 | 14 | 6 | 4 | 0 / 0 |
| 两跳、两个位置，对所有问题启用 | 158 | 6 | 4 | 1 / 1 |
| **两跳、两个位置，按问题启用** | **14** | **6** | **5** | **1 / 0** |

- Technology 的 `multi_hop_2` 沿 `Msg_638 → Msg_832 → Msg_847` 找回了支持消息，排在第十位。一跳和只留一格均错过了它。
- Manufacturing 的 `multi_hop_24` 找到了 `Msg_29329`，但它的内容分数不足以进入前十。原 BM25 已找到的四条支持在选定规则下保留了原排名。
- 较早的试验让回复继承部分起点分数，改变了 88 道题的前十，最终只命中 3/15。它挤掉了 Manufacturing 的 `knowledge_update_10` 原排第十的支持消息，因此保留回复自身的内容分数。

选定规则只改变了 11 道多跳题、2 道时间题和 1 道拒答题。这 14 道题原 BM25 答对 4 道、答错 10 道。在全部 179 道开发题上，原 BM25 答对 56 道，Dense 答对 58 道。即使这 10 道错题全部修复，若另外 169 道判定保持一致，总体准确率也只提升 5.59 个百分点。规则是在开发集上选定的，15 条标注又来自已知失败，检索命中本身不能给出实际的问答提升。冻结测试集有 536 题。

金融服务器上的 CPU 单进程计时覆盖全部 179 题。索引已经建好，每题执行一次 `rank_content`，中位用时 92.21 ms。同一题复用该分数，预热一次 `expand` 后计时 11 次，取每题中位数。179 个题级中位数的中位值为 0.010 ms，P95 为 0.032 ms。计时使用 Python 3.10.20 的 `perf_counter_ns`，只覆盖检索和扩展阶段。

## 复现

```bash
git submodule update --init external/GroupMemBench
python scripts/probe_reply_retrieval.py
```

脚本会在全部 179 道开发题上逐条核对原 BM25 的消息 ID 和分数，输出上述消融表、15 条标注记录和 14 道变化题的完整最终排序。已有本地权重时，可用下列命令复现问答实验。

```bash
python scripts/run_local_baselines.py --methods bm25-reply --full --partition dev \
  --domains Finance Technology Healthcare Manufacturing \
  --model "$QWEN_MODEL" --model-revision b968826d9c46dd6066d109eabc6255188de91218 \
  --embedding-model "$E5_MODEL" --embedding-revision ffb93f3bd4047442299a41ebb6fa998a38507c52 \
  --output results/runs/bounded-reply-dev
```

运行前将两个环境变量设为 Part 1 使用的本地模型目录，并选择新的输出路径。`bm25-reply` 不构建 E5 索引。若使用多卡独立分片，合并时也显式指定 `--methods bm25-reply --partition dev`。资源与划分约定见[实验协议](experiment-protocol.md)。
