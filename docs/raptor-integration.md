# RAPTOR in SGMem

RAPTOR embeds, clusters, and summarizes text recursively. The adapter uses the official `ClusterTreeBuilder`, global and local UMAP, and Gaussian mixture models with BIC model selection and soft membership. The tree starts from single-message text fragments. Its leaves map to original GroupMemBench message IDs, and each summary records its literal child node IDs. A child may appear under more than one parent. [RAPTOR paper](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8a2acd174940dbca361a6398a4f9df91-Abstract-Conference.html) · [Official builder](https://github.com/parthsarthi03/raptor/blob/7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767/raptor/cluster_tree_builder.py)

## Source and runtime

Stage the official MIT-licensed repository at commit `7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767` in a separate checkout. The following checks assume `SGMEM_ROOT` and `RAPTOR_ROOT` are absolute paths to the two checkouts. Run the patch once on the clean pinned RAPTOR checkout, then keep it available as an import root. [Pinned source and license](https://github.com/parthsarthi03/raptor/tree/7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767)

```bash
test "$(git -C "$RAPTOR_ROOT" rev-parse HEAD)" = 7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767
git -C "$RAPTOR_ROOT" apply --check "$SGMEM_ROOT/patches/raptor.patch"
git -C "$RAPTOR_ROOT" apply "$SGMEM_ROOT/patches/raptor.patch"
export PYTHONPATH="$SGMEM_ROOT/src:$RAPTOR_ROOT"
python -c 'import raptor; print(raptor.__file__)'
```

Keep SGMem's existing Torch, Transformers, Sentence Transformers, and NumPy runtime. The upstream imports used by this path also require `umap-learn`, `scikit-learn`, `scipy`, `openai`, `tenacity`, and `tiktoken`, with `numba`, `llvmlite`, and `pynndescent` resolved by UMAP. Record the installed versions in the pilot manifest and validate them together before freezing the runtime. The patch makes FAISS import lazy and removes eager `cl100k_base` loading, so this path can use the existing Qwen tokenizer without downloading a tiktoken vocabulary. [Upstream requirements](https://github.com/parthsarthi03/raptor/blob/7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767/requirements.txt) · [Upstream clustering](https://github.com/parthsarthi03/raptor/blob/7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767/raptor/cluster_utils.py)

The patch supplies seed 224 to both UMAP passes. BIC and the final GMM retain their upstream seeds, 224 and 0. Memberships are propagated by row position, which keeps identical embedding rows tied to the right inputs. A row with no membership above the threshold receives its highest-probability component. If a proposed layer would produce as many or more parents than current nodes, the builder stops at the previous layer. Seeded CPU clustering still requires the same versions and threading configuration for comparisons. [Local source patch](../patches/raptor.patch)

## Build and retrieve

`build_raptor(messages, encoder, tokenizer, summarize, *, config=RaptorConfig(), provenance=...)` accepts one domain's exported messages, the pinned E5-small-v2 encoder, the pinned Qwen fast tokenizer, and a callable `summarize(context, max_tokens)`. The SGMem profile fixes 100 tokens per leaf, a 256-token generation and node ceiling per summary, up to 5 layers, a 3,500-token cluster limit, UMAP reduction dimension 10, and a 0.1 GMM membership threshold. The Qwen prompt targets roughly 50 words. The 256-token ceiling gives Qwen room to finish after the first pilot response reached the original 100-token cap. The build records the configured ceiling in the tree, manifest and per-call receipts. Token limits are measured by the Qwen tokenizer. Leaves embed source body text with `passage: `, and queries use `query: ` plus the same optional asker prefix as Dense. Original source metadata stays with the recovered raw messages. A summary sees the text of its children without benchmark questions or labels.

Oversized groups are reclustered while partition size shrinks and depth permits. An oversized group that cannot progress is split in node order into token-bounded groups. The adapter checks the entire cluster context and the returned summary length. `LocalQwenSummarizer` is a direct loopback HTTP client for an OpenAI-compatible endpoint such as `http://127.0.0.1:18951/v1`. Set `context_tokens=8192` for a server started with an 8,192-token model limit. The client requires non-thinking Qwen mode, matching prompt-token usage, and a normal stop. Custom local callables must enforce the same context ceiling and completion checks. A model or budget failure aborts the current tree build before a cache is returned.

The build CLI runs one summary worker by default. `--summary-workers N` lets the pinned builder submit summaries for one level concurrently while sharing a locked E5 encoder. Each request has its own client and a complete JSONL receipt. Node IDs are assigned in cluster order and the completed level is sorted by ID before the next clustering step. A failed worker aborts the build and cancels requests that have yet to start. The chosen worker count is recorded in the tree and manifest.

Save the returned `RaptorTree` to a `.npz` file with `tree.save(path)` and reload via `RaptorTree.load(path)`. The cache uses UTF-8 JSON for the configuration, source digest, node texts, edges, and leaf IDs, with an array for E5 vectors. It uses NumPy loading with `allow_pickle=False`. Pass the embedding and summary model revisions, tokenizer revision, runtime versions, actual loaded upstream path and patch hash as `provenance` in a recorded pilot. The cache fingerprint covers the domain's ordered normalized source rows. Compare the saved provenance against the planned runtime before reusing an index.

`RaptorRetriever(messages, tree, encoder, tokenizer)` provides two views of the same index. `retrieve_nodes(query, top_k, max_context_tokens=3500, ...)` ranks all levels together by E5 cosine and returns native node text, child IDs, and descendant source IDs in a shared token-capped context. `retrieve(query, top_k, ...)` propagates the best node score to its descendant leaves and returns original messages ranked by the highest propagated score. Ties use direct leaf similarity and stable original-message order. Returned hits expose the winning node ID, layer, and leaf ID. Use `leaf_only=True` on the same cached tree for the leaf-only ablation in either view. The SGMem QA comparison sends ten original messages with its established format and evaluator. Native node evaluation has its own 3,500-token context protocol. [Official collapsed retrieval](https://github.com/parthsarthi03/raptor/blob/7da1d48a7e1d7dec61a63c9d9aae84e2dfaa5767/raptor/tree_retriever.py#L157)

CPU tests exercise the SGMem hooks with fake models, split-message reconstruction, soft-membership provenance, retrieval, cache round trips, and loopback request checks. A temporary patched source checkout also ran the official cluster builder with real scikit-learn GMM and BIC, a mock UMAP projection, and mock models. That check confirmed row identity for duplicate embedding vectors and two summaries on twelve synthetic inputs. A live smoke test still needs to validate the packaged dependencies together, real UMAP, model inference, cluster growth, and timing before full-domain indexing.
