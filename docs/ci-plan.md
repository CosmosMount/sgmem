# 后续 CI 验收清单

目前尚无项目代码、测试或 CI 工作流，以下是实施目标，不代表检查已启用。每项随对应功能合并时落实；CI 优先使用离线、CPU、合成数据，避免依赖 GPU、私有凭据、模型下载或付费服务。

| 检查 | 启用条件 | 通过标准 |
| --- | --- | --- |
| 格式与静态检查 | 确定项目工具和 Python 配置 | 项目自身代码通过约定的格式和 lint；不检查上游子模块 |
| 数据契约与 split | 数据适配和划分实现 | 消息/问题 ID 唯一、领域命名空间正确、划分无重叠，缺失元数据处理明确 |
| 无泄漏 | 可见性过滤与检索请求实现 | 合成数据验证检索输入不含参考答案、标注证据 ID 或正确群组，且检索结果不含超出允许时间范围的消息 |
| 检索及评测 | 检索器和评测实现 | 候选排序、top-k、确定的并列规则、方法间问题覆盖和失败状态符合契约 |
| 最小端到端 | runner 实现 | 用合成样例与轻量替身完成数据到指标的流程，产物写入临时目录，不访问网络或模型服务 |
| 子模块 | 工作流支持 Git 检查 | `.gitmodules` 中声明的路径与父仓库 gitlink 一致；检出时使用记录的提交，且子模块工作树干净。网络不可用时报告检出失败或未运行 |
| 产物与秘密 | 文件分类规则确定 | 检查主仓库新增/跟踪文件是否包含明确禁止的临时产物、密钥或大型数据；不扫描子模块内容，允许经确认的正式交付物 |

每个检查应有清晰的执行命令、输入范围和失败信息，并能在本地运行。临时文件由测试框架或工作流清理。无效封装、代码重复、必要性、科研结论与文档质量需要人工审查；CI 不能凭名称或行数可靠判断。未来若使用 submodule checkout，需确保工作流检出父仓库固定 gitlink，而非追踪上游分支；依赖网络的检查结果与离线测试结果分别呈现。
